Tool-using agents built on large language models can now initiate payments, change account details and send data to external recipients. Indirect prompt injection — content placed in a tool output or a retrieved document that the agent then follows — can make such an agent propose a financial action that serves an attacker rather than the user.

This thesis designs, implements and evaluates the Runtime Evaluation and Mitigation (REM) framework, a five-layer runtime layer placed at the tool-execution boundary. For each proposed tool call, REM estimates the probability that the call was adversarially induced, using ridge logistic regression calibrated on the logit; assigns a declared consequence tier; applies policy predicates; selects one of four verdicts (Allow, Modify, Escalate or Block) by minimizing expected loss under tier-indexed costs; and records every verdict for audit, with an attribution that cannot influence the verdict. Each constituent mechanism is established in prior work; the contribution is the combination and its evaluation.

The framework was implemented in Python and verified by automated tests. It was evaluated in an exploratory study on recorded traces of 21 real LLM agents in the AgentDojo banking environment (3,334 episodes; 6,762 proposed tool calls), using nested grouped cross-fitting that holds out whole attacker objectives; a re-execution of the full pipeline in a fresh environment reproduced every analytical result. On held-out attacker objectives, the evidence available at the tool boundary separated attack attempts from legitimate calls (pooled ROC-AUC 0.938). Most of this separation came from evidence about the action's arguments; calibration produced no observed improvement; and the behavioral features were not specific to attacks in this benchmark.

With the declared exploratory costs, the expected-loss rule intervened on 97.3% of attack steps and on 22.7% of legitimate steps, against 74.0% and 5.6% for a baseline that uses the same estimator but ignores consequences. In a replay that assumes the agent does not adapt to refusals, REM's attack success rate was 0.004, against 0.055 for the baseline (step-level mitigation; 0.046 for the baseline under the episode-level variant). Without a reviewer, benign task success fell from 50.9% under the baseline to 31.4%; with an idealized reviewer the loss disappeared.

A closed-loop integration in which a running agent receives REM's refusals and may retry or replan was implemented and tested with scripted test agents, but it was not executed with a language model. The results are therefore exploratory: they do not show protection of a live or adaptive agent, which remains the first item of future work.

**Keywords:** AI agent security; indirect prompt injection; runtime monitoring; financial AI agents; tool-use security; probability calibration; expected-loss decision; human escalation; AgentDojo.
