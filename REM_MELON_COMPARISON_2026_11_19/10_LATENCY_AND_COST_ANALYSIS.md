# 10 Latency and cost analysis

**Different quantities, never compared as one.**
- **REM's** overhead is a CPU computation per proposed tool call.
- **MELON's** overhead is additional **model calls** (a masked re-execution after each tool turn) and **embedding calls**.

**What these timings cover.**
- REM makes **no model call**: zero tokens and no inference cost.
- The timings vary between runs on shared machines. None is a deployment latency.

## 2 MELON: added model and embedding calls (structural, measured from recorded trajectories)

**Source:** `results/workload_estimate.json`, generated by `experiments/rem_vs_melon/estimate_volume.py`.
- **Data:** the 160 recorded gpt-4o banking runs (144 attacked, 16 benign), on the undefended trajectory.
- **Model of the arms:** taken from the code (see the script header).
- **Status:** a planning estimate, not a measurement of the MELON arm. Detection may stop episodes early, which would lower MELON's counts.

| Quantity (one repeat, 160 episodes) | D0 or D1 | D2 MELON | D2 relative to D0 |
|---|---|---|---|
| Agent model calls | 602 | 602 + **442** masked | +73% calls |
| Input characters sent to the model | 3.52 M | 3.52 M + **4.87 M** | +138% input characters |
| Output characters (lower bound, agent only) | 0.076 M | ≥ 0.076 M + masked outputs | – |
| Embedding calls | 0 | ≤ **884** | – |

**Why the masked context is large.** Each masked call carries:
- upstream's fixed few-shot dialogue (≤ 4.9 k characters);
- all tool outputs so far;
- the tool schemas (4.3 k characters).

**Full design.** 3 arms × 160 episodes × 1 repeat ≈ **2,248 model calls** and **15.4 M input characters**.

## 3 Dollar cost: NOT ESTIMATED

**What a dollar figure needs:**
- a tokenizer, to turn characters into tokens. The `o200k`/`cl100k` files are not reachable.
- the provider's **current** prices for the chosen agent model and `text-embedding-3-large`. Neither price page is reachable, and prices are **not guessed**.

**Formula for the operator:**

```
cost = Σ_calls (input_tokens × p_in + output_tokens × p_out) + Σ_embeddings (tokens × p_emb)
```

- **Tokens:** the provider's reported `usage`. The runner's spending guard records it per call; for planning, apply a tokenizer to the characters above.
- **Cap:** the guard refuses any call that would exceed `budget.cap_usd`.
- **Reservation:** before each call it reserves a worst-case amount: characters / 2.0 tokens, plus 2,048 output tokens.
