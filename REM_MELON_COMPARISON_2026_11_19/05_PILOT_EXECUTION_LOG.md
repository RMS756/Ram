# 05 Pilot execution log (19 November 2026)

## What could be piloted

**The live LLM pilot is NOT EXECUTED.** There is no model and no embedding endpoint (`03`).

**What was run instead.** A **scripted integration pilot** of the same three-arm harness that a live run uses (`experiments/rem_vs_melon/harness.py`):
- in the MELON environment (AgentDojo 0.1.29);
- with the **unmodified official MELON file**, sha256-checked;
- with the **frozen REM v1.0 bundle**.

Two test doubles replace the model-dependent parts. They are stated with every number below.
- **Agent: "ReactiveCompliantAgent".**
  - It issues the user task's ground-truth calls, one per turn.
  - When a tool output contains the `<INFORMATION>` payload marker, it next issues the injection task's ground-truth calls, i.e. it obeys the injection.
  - In MELON's masked context, it issues the injection's first call if the masked tool contents contain the payload.
  - It does not read refusals, retry or reason.
- **Embeddings: "TrigramHashEmbeddings".** Deterministic character-trigram hashing vectors. **Not `text-embedding-3-large`.** MELON's own threshold (0.8) is unchanged.

**These counts are integration diagnostics.** They are **not** attack-success, utility or comparison results, and they are not plotted as such.

## Runs

| Run | When | Cases | Outcome |
|---|---|---|---|
| Smoke 1 | 19 Nov | 9 attacked + 4 benign (`pilot` set) × 3 arms | Ran without error, but **no attack was attempted in any arm**. Diagnosis: the scripted agent searched tool outputs for the payload string verbatim, while AgentDojo serialises it inside YAML-formatted tool output. **Fix** (test double only, not REM, not MELON): match the payload's fixed `<INFORMATION>` marker. |
| Smoke 2 | 19 Nov | same 13 cases | All mechanisms active (table below, pilot scale) |
| Full | 19 Nov | **144 attacked + 16 benign × 3 arms = 480 episodes**, 19.6 s | 0 errors; all mechanisms active (`results/scripted_pilot_full/`) |

**Finding of the pilot.** AgentDojo returns `security = True` for **benign** episodes, which have no injection task. Attack success must therefore be read **only on attacked episodes**. The analysis code and protocol `06` do so.

## Integration differences that matter for a live run

These do **not** invalidate the comparison; they are reported with it.
1. **REM continues after a refusal; MELON stops the episode.** Under a live model, REM's utility under attack depends on whether the agent re-plans; MELON's is capped by early stopping.
2. **MELON does not inspect the first assistant turn.** Calls proposed before any tool output pass unchecked; REM evaluates them.
3. **MELON roughly doubles model calls after the first turn.** REM adds no model call.

## Measurement taken from the pilot that does not depend on the agent

**REM's per-call decision latency** (complete-call timer, CPU, 522 decisions):
- median **0.272 ms**;
- p95 **0.524 ms**.

This is the cost of REM's own computation. It is still not a deployment latency.
