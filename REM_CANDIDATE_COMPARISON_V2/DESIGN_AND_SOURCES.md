## Four distinct mechanisms

**C1 — action-only learned REM.** Refit original ridge logistic on fixed x_act1/x_act2/x_act3, preserving the original lambda grid, OOF logit calibration, expected-loss rule, consequences, predicates and step-level mitigation. This is a feature-group reduction, not a new learned mathematical method. Hyperparameters are chosen only from each fitting portion's inner folds. Both objective-disjoint and user-task-disjoint outer fitting were executed.

**C2 — canonical provenance.** Enforce the declared banking mutation schema and block a key argument found only in lower-trust context. IBAN matching handles spaces, hyphens, case and format characters with token boundaries. Numeric/text matching otherwise follows the original REM helper. It is a rule, not a calibrated probability or complete authorization proof. Unknown argument provenance can still pass. Its strict ID typing rejects a numeric string that AgentDojo itself casts to an integer; the measured utility cost is disclosed rather than tuned away after testing.

**C3 — target-focused diagnostic control.** Same as C2 but omit amount provenance for transfer tools. This tests whether the benchmark's recipient-dominated labels conceal weaknesses. It deliberately does not protect a changed amount to an otherwise authorized recipient; the stress suite demonstrates this. It is not recommended despite zero benchmark ASR.

**C4 — verified refund capability.** Recognize a bounded full trusted-user request of the form “refund ACCOUNT for what they sent me”. Independently inspect only own-account identity and transaction id/sender/recipient/amount/date, using a narrow host adapter on the actual current simulated bank environment. It never reads task solutions, attack IDs, clean pre-injection snapshots, files, profile secrets or transaction notes. A unique incoming receipt supplies recipient/amount/date; declared policy supplies the safe subject `Refund`. Repair replaces the entire proposed argument map with this justified action, and a one-use reservation prevents repeat execution. Ambiguous/missing/untrusted evidence withholds execution; other mutation tools are not authorized. Outside this bounded grammar it falls back to C2.

The native fixture's local-account alias `me` is resolved by the trusted backend adapter only; agent arguments do not receive that privilege. Authentication is a **host trust assertion**, not an implemented bank certificate verifier. A real connector must establish authenticity, account scope, freshness, atomic reservation and review handling. This changes the available evidence relative to ordinary REM and is not a free or universally deployable capability.

## Source and equation classifications

- Original ridge/logit calibration/Bayes mathematics is reused unchanged. Its sources and unresolved exact equation-number/authoritative-registry issues are documented in the previous study's `03_PUBLISHED_ALGORITHM_FOUNDATIONS.md`. No new registry IDs are assigned and no inherited conflict is declared resolved.
- [PROVISO v1](https://arxiv.org/html/2610.27115v1), §3.1, distinguishes licensing of operations/targets from external argument support. This informs the **engineering concept**, not a claim that C4 reproduces its network or Eq. (7).
- [CaMeL](https://arxiv.org/html/2503.18813), §5.2–5.4, supplies prior art for capability policies. C4 does not reproduce its interpreter or guarantees.
- [Calibration Is Not Control v2](https://arxiv.org/html/2606.21399v2), Eqs. (1),(3), requires outcomes of alternative interventions; none is manufactured here. Original NO-ADAPT oracle-withholding r_mod is retained as an inherited surrogate, not relabeled intervention-value learning.
- [CASEL](https://arxiv.org/html/2610.36570v1), Eq. (2), motivates explicit verification options, but its effectiveness/cost parameters are not copied into banking. No such cost function is introduced.

Schema checks, bounded parsing, string normalization, source matching, exact repair and reservation are engineering logic. There is no new numeric authorization score, confidence formula, severity multiplier, learned branch utility, arbitrary security threshold or bank-loss coefficient. Four actions retain precise semantics: original C1 Modify withholds (legacy declared mechanism), whereas C4 Modify actually executes trusted replacement arguments. Neither meaning is silently applied to official REM.
